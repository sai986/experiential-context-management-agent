## 1. Problem Statement

Long-horizon LLM agents accumulate many observations, constraints, intermediate outputs, distractors, and failed attempts. Keeping everything in context increases token cost and may add noise. Compressing or removing information reduces context size but can delete important facts such as exact numeric values, negations, hard constraints, or delayed dependencies.

Our project studies whether a context-management agent can learn which information should be kept, compressed, archived, restored, or later retrieved. The key idea is to use counterfactual replay: when the task fails, we change an earlier context-management decision and check whether the downstream outcome improves. Only decisions with supported effects are converted into reusable context-management lessons.

## 2. Research Question

Can an experiential context manager improve long-horizon task performance by learning reusable context-management lessons from counterfactual replay, without retraining the frozen task-solving agent?

## 3. Current Progress

For the mid-submission checkpoint, we implemented a minimal controlled pilot. The current codebase includes:

- controlled synthetic task generation;
- deterministic evaluator;
- immutable context ledger;
- context-management actions for KEEP, COMPRESS, ARCHIVE, and RESTORE;
- full-context, fixed-compression, and non-learning-manager baselines;
- counterfactual replay by restoring original content after harmful compression;
- lesson creation from attributed failures;

The current version intentionally uses a deterministic simulated task agent. This allows us to test the causal attribution and lesson loop without API-key dependencies or hosted-model nondeterminism. In the final version, this can be replaced or supplemented with a frozen hosted LLM.

## 5. System Architecture Implemented

The implemented pilot follows this flow:

```text
Controlled task
  -> context ledger stores raw observations
  -> context manager applies KEEP / COMPRESS / ARCHIVE / RESTORE
  -> frozen deterministic task agent answers from managed context
  -> evaluator scores answer
  -> failed episodes trigger counterfactual replay
  -> replay restores original compressed fact
  -> improved outcome creates a reusable lesson
  -> lesson-aware manager uses lessons on held-out tasks
```

We implemented three baseline conditions:

| Condition | Description |
|---|---|
| `full_context` | Gives all observations to the task agent without compression |
| `fixed_compression` | Compresses older context using a fixed strategy |
| `non_learning_manager` | Uses context-management rules but no learned lessons |

The proposed mid-submission method is:

| Condition | Description |
|---|---|
| `attributed_lesson_manager` | Uses lessons learned from counterfactual replay of previous failures |

## 7. Ablations

The current pilot supports these ablations:

| Ablation | Comparison | What It Tests |
|---|---|---|
| Full context vs fixed compression | `full_context` vs `fixed_compression` | Whether naive compression loses critical information |
| Non-learning vs lesson-aware manager | `non_learning_manager` vs `attributed_lesson_manager` | Whether learned context-management lessons help |
| Compression without attribution vs with attribution | `fixed_compression` / `non_learning_manager` vs `attributed_lesson_manager` | Whether replay-backed lessons prevent repeated failures |

## 10. Challenges Faced

| Challenge | Impact |
|---|---|
| Scope is large | Full system includes memory, attribution, lessons, baselines, and transfer |
| Hosted LLM replay can be costly | Counterfactual replay multiplies model calls |
| Hosted models are stochastic | Same prompt may produce different outputs across runs |
| False causal claims are possible | Reflection alone can blame the wrong context decision |
| Cross-agent transfer is difficult | Lessons may help one agent but harm another |
| Time before mid-submission is short | We needed a minimal defensible pilot first |

## 11. Mitigation Plan

| Risk | Mitigation |
|---|---|
| Scope explosion | Start with two controlled task families and one replay intervention |
| Replay cost | Use controlled deterministic pilot first; add repeated hosted-model runs later |
| False attribution | Store a lesson only when counterfactual replay improves outcome |
| Dataset ambiguity | Use synthetic tasks with known critical facts and forbidden outputs |
| Negative transfer | Measure Agent-A to Agent-B transfer separately in final submission |
| Weak baselines | Compare against full context, fixed compression, and non-learning manager |

## 14. Current Limitations

- The current task agent is deterministic and simulated.
- The test split is small.
- Current replay supports only restore-after-compression.
- RETRIEVE is part of the design but not yet implemented in the pilot.
- Results are from controlled tasks, not open-ended long-horizon benchmarks.
- Cross-agent transfer is planned for final submission, not completed yet.

## 15. Conclusion

The mid-submission implementation demonstrates the core project loop: context decisions are recorded, harmful compression can be identified through counterfactual replay, validated lessons are stored, and those lessons improve later controlled tasks under the same pilot setup. The final phase will focus on scaling the benchmark, adding hosted LLM agents, expanding ablations, and evaluating cross-agent transfer.
